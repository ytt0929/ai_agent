# 工作台与智能尽调融合方案讨论稿

## 1. 基本定位

工作台不是简单跳转到智能尽调页面，而是智能尽调的一个 AI 发起入口。

建议统一为：

```text
工作台 = AI 发起入口 + 跨工具编排入口
智能尽调 = 尽调任务详情入口 + 深度处理入口

两者共用同一套“尽调任务工作区”：
DueTaskHeader + DueFlowProgress + DueStageResultPanel
```

工作台前半段保留筛客、企业探查、监控、新建尽调等工具编排感；用户确认新建尽调后，左侧切换成智能尽调任务工作区，右侧继续保留 AI Copilot 对话。

## 5. 交互原则

```text
右侧对话 = 事件入口
左侧工作区 = 状态结果展示
顶部流程条 = 全局进度导航
```

右侧 AI 不承载大结果，只负责解释、确认、推进和快捷动作。

## 6. 节点左侧展示总览

```text
工商核验   → 企业基础信息 + 主体状态 + 司法风险 + 关联企业
司法查询   → 诉讼/执行/处罚/裁判文书结果
税票采集   → 授权状态 + 采集进度 + 发票/申报结果 + 日志
资料补充   → 资料包完整度 + 已收集 + 缺失资料 + 识别字段
证据整合   → 工商证据 + 税票证据 + 资料证据 + 风险关联证据
风险诊断   → 风险评分 + 风险事项 + 诊断结论 + 建议措施
产物确认   → 报告草稿 + 资料包 + 附件清单 + 待确认项
```

## 9. 节点交互话术与流程推进

右侧 AI Copilot 的话术分成三类：状态说明、用户确认、推进下一步。每个节点都不要让 AI 一次性输出太多内容，而是像流程主持人一样，一步一步把用户带到下一个节点。

整体推进链路：

```text
智能筛客
  ↓ 选择企业 / 用户确认探查
企业探查
  ↓ 用户选择：加入监控 / 新建尽调
新建尽调
  ↓ 用户选择模板
工商核验
  ↓ 自动完成后进入司法查询
司法查询
  ↓ 自动完成后进入税票采集
税票采集
  ↓ 用户确认发送授权链接 / 模拟企业授权
资料补充
  ↓ 用户确认模拟上传 / 标记资料满足
证据整合
  ↓ AI 自动整合完成
风险诊断
  ↓ 用户查看诊断 / 确认同步报告
产物确认
  ↓ 用户点击编辑报告
报告编辑模式
  ↓ 用户确认 / 修改 / 导出
完成
```

### 10.1 产物名称与报告底稿关系

```text

- 尽职调查报告

- 税票分析报告
```

其中：


## 11. Phase 3：智能尽调任务台账与工作台同步规划

工作台发起的尽调不能表现为一次性自动跑完的脚本，而应该沉淀为一个可持续推进的尽调任务。

三类页面的定位如下：

```text

- 流程进度
- 左侧阶段产物

- 税票/资料等待状态

- 工作台创建任务后，智能尽调首页能看到
- 智能尽调推进后，工作台能看到当前阶段

- 产物确认后生成报告草稿
```

优先级建议：

```text

```

## 12. 产物确认、报告预览与报告编辑的三态交互

### 12.1 产品判断

产物确认阶段不能把「尽职调查报告」作为一个小卡片简单展开。尽职调查报告是完整文档，内容长、章节多，需要足够阅读空间。

```text

  ├─ 导出报告
  └─ 返回产物确认 → 产物确认列表态

  ├─ 预览报告 → 报告预览态
  ├─ 保存草稿
  ├─ 导出最终报告
```

右侧 AI Copilot 始终保持存在，用于改写风险结论、补充税票说明、生成授信建议和导出最终报告。

### 12.5 样式约束

该部分必须符合项目全局 UI 体系：

```text
1. 组件优先使用 Element Plus：el-card、el-table、el-tag、el-button、el-descriptions、el-divider、el-input、el-scrollbar。
2. 样式必须优先使用 src/styles/tokens.css 中的 CSS 变量。
3. 禁止新增大面积硬编码颜色、复杂渐变、大阴影、大圆角、装饰性图标。
4. 文档预览要像后台系统里的 PDF/Word 预览，不要做成营销页。
5. 右侧 AI Copilot 始终保留，不被 drawer 或弹窗覆盖。
```
