# 企业探查产品方向沉淀

## 产品定位

企业探查是面向银行客户经理的企业数据分析 Agent。

它不是单纯的工商查询，也不是打开后直接生成企业诊断报告。它应该以对话为入口，支持客户经理围绕一家企业进行多轮追问，并根据问题复杂度决定输出形态。

核心定位：

- 先基于工商、司法等公开信息完成基础识别。
- 当问题涉及税票、纳税、经营真实性、资金流闭环、欺诈信号时，引导用户授权税票或上传流水、补充材料。
- 简单问题在对话中直接回答。
- 复杂问题在左侧工作区打开结构化分析视图。
- 报告是沉淀结果，不是所有问题的默认承载方式。

## 与智能尽调的关系

企业探查是独立 Agent，也可以作为智能尽调里的风险识别能力。

智能尽调中的“风险诊断 / 风险识别”可以调用企业探查能力，获取风险指标、欺诈信号、证据链和诊断结论。

企业探查更偏“自由探索和解释”，智能尽调更偏“流程化任务处理和材料闭环”。

## 能力分层

### 1. 事实查询类

适合直接在对话中回答，必要时返回轻量表格或明细列表。

示例：

- 查看社保费明细
- 查看股东明细
- 查看申报信息明细
- 查看近 12 个月开票金额
- 查看法人、成立时间、行业、纳税信用等级
- 查看主要客户、供应商、处罚记录

目标效果：

用户问一个明确数据点时，不跳报告页，不打开大页面，只在对话中快速回答，并提供“展开完整明细 / 加入报告 / 查看证据来源”等操作。

### 2. 指标计算类

适合在对话中给出计算结果、公式、口径和数据来源。

示例：

- 计算税负率
- 计算收入同比
- 计算申报收入和开票收入差异
- 计算客户集中度
- 计算社保人数和收入规模是否匹配
- 计算供应商集中度或交易异常比例

目标效果：

用户得到的不只是一个数，而是“结果 + 计算口径 + 数据来源 + 是否异常 + 下一步建议”。

### 3. 结构化分析类

适合在左侧工作区打开分析视图，右侧继续保留对话。

示例：

- 这家企业经营情况如何
- 近 12 个月收入趋势如何
- 是否存在税负异常
- 是否存在疑似欺诈行为
- 工商司法风险如何
- 纳税全景怎么看
- 某个风险指标的证据链是什么

目标效果：

左侧展示结构化视图，例如经营分析、纳税全景、工商分析、风险诊断、欺诈信号、证据链；右侧 AI 继续解释、追问、生成专项说明。

### 4. 报告生成类

适合在用户明确需要沉淀材料时触发。

报告类型需要区分：

- 工商分析报告：基于工商、司法、股东、经营状态等公开数据。
- 纳税全景报告：基于税票、申报、税负率、纳税信用、税务异常等数据。
- 企业诊断报告：基于更完整的数据覆盖，输出多维度风险、亮点、证据链和行动建议。

目标效果：

报告不是默认页。只有用户点击“生成报告 / 加入报告 / 查看完整诊断报告”时，才进入报告输出。

## 数据覆盖策略

企业探查应先判断数据覆盖：

- 工商已获取：可做企业识别、工商司法基础分析。
- 司法已获取：可做司法负面、诉讼、处罚等分析。
- 税票已授权：可做纳税全景、税负率、开票收入、申报差异分析。
- 流水已上传：可做资金流闭环、经营真实性、欺诈信号增强判断。
- 尽调未发起：可将风险信号推送到尽调任务。

当数据不足时，不应该假装完成完整诊断：

- 缺税票：提示“当前只能基于工商/司法公开信息完成基础探查，如需判断税负异常、纳税全景，请授权税票。”
- 缺流水：提示“当前无法完整判断资金流闭环和收入真实性，如需识别疑似欺诈，请上传流水。”

## 推荐交互流程

1. 用户在企业探查首页输入企业名称、税号或自然语言问题。
2. 进入对话式工作台，先保持对话优先。
3. AI 用打字机方式回应：正在识别企业、检查数据覆盖、判断问题类型。
4. 系统展示轻量探查过程，而不是直接跳结果页。
5. 如果是事实查询或指标计算，在对话中直接回答。
6. 如果是复杂分析，左侧打开对应结构化视图，右侧继续保留 AI 对话。
7. 如果需要完整沉淀，再生成工商分析报告、纳税全景报告或企业诊断报告。
## 2026-07-02 补充：对话优先的企业探查工作区设计

### 1. 产品定位补充

企业探查应定位为「自然语言驱动的企业数据问答 + 结构化探查工作区」。

它不是每问一句都打开一个大结果页，也不是纯聊天窗口。正确的体验是：

```text
用户自然语言提问
   │
   ├─ AI 识别企业
   ├─ AI 判断问题类型
   ├─ 轻问题在对话中直接回答
   ├─ 明细和分析类问题在左侧打开结构化结果
   └─ 报告 / 尽调 / 监控作为后续动作承接
```

### 3. Demo 固定企业策略

Demo 阶段需要优先保证链路稳定。企业探查 `_new` 页面没有企业上下文时，应默认使用：

```text
企业名称：唐山物桥商贸有限公司
统一社会信用代码：91130203MA7EEQ2N0T
```

推荐体验：

```text
进入 /enterprise-diagnosis/workspace/_new?q=计算税负率
   │
   ├─ 输入框默认填入：91130203MA7EEQ2N0T
   ├─ AI 提示：已为你填入演示税号，点击发送即可识别企业并继续处理当前问题
   ├─ 用户点击发送
   ├─ AI 识别：唐山物桥商贸有限公司
   └─ 自动继续处理 pending question：计算税负率
```

这样可以避免演示人员不知道该输入什么，也避免「问题已经带入但企业未识别」造成的卡顿感。

```text
左侧展示诊断报告 / 风险事项 / 证据链
```

### 5. 流式输出稳定策略

当前企业探查的 Demo 目标应是「稳定第一，流式第二」。

推荐将 AI 输出统一收口为安全流式消息：

```text
用户发送问题
   │
   ├─ lockInput()
   ├─ ensureEnterpriseContext()
   ├─ classifyQuestion()
   ├─ buildFullAnswer()
   ├─ safeStreamMessage(answer)
   ├─ attachActions()
   └─ unlockInput()
```

关键约束：

```text
1. 不允许多个 AI 回复同时流式输出。
2. 不要在业务逻辑中分散调用未 await 的 typeAiMessage。
3. runExploreFlow 必须使用 try/finally 释放 isExploring。
4. 流式输出期间应节流滚动到底部。
5. Demo 关键答案可分段或整段输出，不强制逐字。
6. action buttons 必须在文本输出完成后再展示。
```

建议结构：

```text
async function runExploreFlow(question) {
  if (isExploring.value) return
  isExploring.value = true
  try {
    const qa = classifyQuestion(question)
    const answer = buildAnswerByType(qa, question)
    await safeStreamMessage(answer.text, { actions: answer.actions })

    if (answer.leftView) {
      openLeftView(answer.leftView)
    }
  } catch (error) {
    await appendAiMessage('当前问题已识别，但回复生成异常。你可以重新发送或点击下方快捷问题继续。')
  } finally {
    isExploring.value = false
  }
}
```

### 6. 与其他模块的关系

企业探查负责「数据到洞察」。

```text
企业探查结果
   │
   ├─ 单点指标 / 单事实
   │     └─ 继续对话
   │
   ├─ 结构化明细 / 风险分析
   │     └─ 左侧打开探查结果
   │
   ├─ 需要持续关注
   │     └─ 加入企业监控
   │
   ├─ 需要授信核查
   │     └─ 新建智能尽调
   │
   └─ 需要沉淀材料
         └─ 生成企业诊断报告 / 加入智能报告
```

企业探查不应把所有问题都变成报告，也不应把所有结果都推入尽调。报告、尽调、监控是后续动作，不是默认输出。

### 7. 当前代码与需求的偏离度

基于当前代码，企业探查已经具备部分基础能力，但与目标体验仍有偏离：

```text
┌──────────────────────────────┬──────────┬────────────────────────────────────┐
│ 目标能力                       │ 偏离度     │ 当前情况                             │
├──────────────────────────────┼──────────┼────────────────────────────────────┤
│ Demo 默认识别唐山物桥             │ 高        │ _new 页面未默认填入 91130203MA7EEQ2N0T │
│ 单指标只在对话回答                │ 低        │ chatOnlyTypes 已覆盖税负率/收入指标      │
│ 明细类左侧展示                    │ 低        │ 股东/社保/申报已能切换左侧视图           │
│ 风险分析左侧展示                  │ 中        │ 风险/欺诈/经营可切换，但边界需收口        │
│ 流式输出稳定                     │ 高        │ typeAiMessage 逐字输出，存在卡住风险      │
│ 状态释放                         │ 高        │ runExploreFlow 多处分支手动释放状态       │
│ 消息并发控制                     │ 高        │ 存在未 await 的 typeAiMessage 调用        │
│ 左侧结果区是否切换的规则统一         │ 中        │ 规则分散在 classifyQuestion 和分支中       │
│ Element Plus + token.css 风格统一 │ 中        │ 部分页面已改造，工作区仍有历史样式         │
└──────────────────────────────┴──────────┴────────────────────────────────────┘
```

### 8. 分阶段解决方案

#### Phase 1：跑通 Demo 主链路和流式稳定

目标：让演示稳定，不再出现 AI 回复卡在一个字、按钮一直「探查中」的问题。

范围：

```text
1. _new 页面默认填入 91130203MA7EEQ2N0T。
2. 如果存在 pendingQuestion，识别企业后自动继续处理。
3. 新增 safeStreamMessage，统一替换核心路径中的 typeAiMessage。
4. runExploreFlow 使用 try/finally 兜底释放 isExploring。
5. 禁止多个 AI 回复同时流式输出。
6. 税负率、收入同比、基本事实等单点问题不切换左侧。
```

验收：

```text
/enterprise-diagnosis/workspace/_new?q=计算税负率
   → 输入框默认有 91130203MA7EEQ2N0T
   → 点击发送
   → 识别唐山物桥商贸有限公司
   → 自动回答税负率
   → 左侧不切换
   → 按钮恢复可用
```

#### Phase 2：统一问题分流和左侧结果区

目标：让「什么时候只对话、什么时候打开左侧」有稳定规则。

范围：

```text
1. 抽象 answer plan：
   {
     replyText,
     actions,
     leftView,
     leftViewPayload
   }

2. classifyQuestion 只负责分类，不直接承担展示逻辑。
3. 统一 openLeftView：detail / analysis / risk / report。
4. 单指标、单事实默认不打开左侧。
5. 明细列表、风险分析、报告生成才打开左侧结果区。
```

验收：

```text
税负率是多少       → 右侧回答，左侧不切换
查看股东明细       → 左侧股东表，右侧解释
是否存在欺诈风险   → 左侧风险诊断，右侧结论和动作
生成企业诊断报告   → 左侧报告，右侧过程和按钮
```

#### Phase 3：企业探查工作区视觉统一

目标：工作区也使用 Element Plus + token.css 风格，和企业探查首页、工作台、智能报告保持一致。

范围：

```text
1. 结果卡片使用 el-card / el-table / el-tag / el-descriptions。
2. 不再使用大量自定义 table 和硬编码颜色。
3. 字体、间距、圆角、边框、背景统一引用 tokens.css。
4. 保留当前业务功能，不改 mock 数据。
5. 保证左右区域独立滚动，不出现页面整体滚动错乱。
```

#### Phase 4：跨模块承接

目标：企业探查结果能自然转入智能尽调、企业监控、智能报告。

范围：

```text
1. 风险分析后提供：加入监控 / 新建尽调 / 生成诊断报告。
2. 报告生成后提供：加入报告 / 编辑报告 / 导出。
3. 新建尽调时带入企业探查风险事项、证据链和数据覆盖状态。
4. 加入监控时带入风险标签和监控规则建议。
```

### 9. OpenClaw 实施注意事项

```text
1. 不要在页面上展示「问题类型分流规则表」。
2. 不要修改已有 mock 数据结构，除非为唐山物桥补齐缺失字段。
3. 不要改侧边栏、路由命名和其他独立模块。
4. 不要批量重写中文文案，避免出现乱码。
5. 修改后必须跑 npm run build。
6. 优先修 EnterpriseExplorationWorkspacePage.vue 的状态机和流式输出，再处理样式。
```
