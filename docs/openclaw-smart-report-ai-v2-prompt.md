# OpenClaw Prompt V2: 智能报告改成 AI Copilot 产品

请修改 `D:\demo\ai-copilot` 项目中的“智能报告”功能。

这次目标不是做一个传统 SaaS 报告管理页，而是做一个 **AI 报告 Copilot**：用户进入页面后，第一感觉应该是“我可以直接让 AI 帮我起草、检查、追问证据、修改报告”，而不是“我在管理一堆报告卡片”。

## 本次你的角色定位

你不是普通前端工程师，也不是只负责还原 UI 的代码助手。本次请同时扮演三个角色：

### 1. 资深 AI 产品经理

- 目标是把“智能报告”从传统 SaaS 报告管理页，改造成 AI Copilot 型产品。
- 判断标准不是页面是否有卡片和列表，而是用户是否能感受到 AI 在主动理解任务、组织证据、检查风险、提出下一步建议。
- 首页必须体现“用户可以直接让 AI 做事”，而不是先让用户管理模板和报表。
- 首页第一视觉必须是 AI 任务输入框和 AI 今日建议，报告列表、模板入口、统计卡都只能作为辅助信息。

### 2. 资深银行业务产品经理

- 你需要理解授信调查报告不是普通摘要，而是银行客户经理用于授信审批的合规调查文档。
- 重点体现证据链、风险依据、缺失材料、待确认事项、审批口径和提交前检查。
- 不要把报告做成营销文案，也不要把 AI 回复做成泛泛聊天。
- 所有 AI 建议都要围绕“能否提交、缺什么证据、风险依据是什么、下一步怎么处理”展开。

### 3. 资深前端工程师

- 你需要直接重写允许修改的文件，修复当前乱码、半截字符串和潜在编译错误。
- 保证 Vue3 + Element Plus 实现稳定，`npm run build` 通过。
- 不要修改智能尽调、路由、侧边栏等边界外文件。
- 代码要清晰、状态简单，不要引入新的 UI 库或复杂架构。

最终目标：

```text
让 /smart-report 看起来像一个银行客户经理的 AI 报告助手，而不是一个传统 SaaS 报告管理后台。
```

## 执行原则

## 1. 产品定位

智能报告不是“报告列表 SaaS”，而是：

```text
AI 报告助手 + 授信调查报告生成器 + 证据审查工具 + 报告局部修改器
```

首页要从：


改成：


- 用户可以直接输入任务，让 AI 处理报告

- AI 明确指出缺什么证据、哪里不能提交、下一步做什么
- 报告编辑页中，AI 要围绕“正文、证据、规则、修改建议”工作

- 全部确认后，点击“提交确认”显示 success。
